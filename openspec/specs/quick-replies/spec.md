# quick-replies Specification

## Purpose
Offer the user one-click next messages: suggested replies generated after an answer, and opening messages from the domain pack for an empty chat.

## Requirements

### Requirement: Suggested replies after a turn
When the configuration enables `suggestions` (default off), a turn that ends with an answer SHALL end with `CUSTOM suggestions {items: [...]}` before `RUN_FINISHED`. It SHALL contain between 1 and `suggestions.max` (default 3) short replies in the user's language. No suggestions SHALL be sent for a turn that ends with a card.

#### Scenario: After an answer
- **WHEN** suggestions are enabled and the agent answers "The Loan tab is open now"
- **THEN** the client receives a `suggestions` event with up to 3 next steps, for example "How much can I borrow?"

#### Scenario: Disabled
- **WHEN** `suggestions` is not configured
- **THEN** no `suggestions` event is sent and no extra model call is made

### Requirement: How suggestions are made
Suggestions SHALL be generated by a separate call to `suggestions.model` (default: the memory role's model), with the last exchange and the form outline as input. A failure, or a timeout after `suggestions.timeout` (default 4 s), SHALL send no event and SHALL NOT fail the turn.

#### Scenario: A slow model
- **WHEN** the suggestions call takes longer than the timeout
- **THEN** the run finishes without a `suggestions` event

### Requirement: Starters for an empty chat
A domain pack MAY define `starters`, a list of opening messages. They SHALL be returned by `GET /threads/{id}` as `starters` when the thread is empty, so a client can show them as chips.

#### Scenario: A new conversation
- **WHEN** a client opens an empty thread for a form whose pack defines three starters
- **THEN** the thread response contains those three starters
