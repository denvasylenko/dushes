# Proposal

## Why

Every team that uses formguide has to write its own chat UI. That means handling AG-UI events, interrupts, frontend tools, restoring a thread, the microphone, and the field-change and question cards. The demo chat works but is plain, and it is tied to the demo app. The chat in the Cheese project (`backend/app/site/chat.js`, "Herefront AI") shows how good a chat can feel:
- an adaptive typewriter, with new words fading in out of a blur and no flicker on redraws;
- a sliding panel, typing dots, a pulsing microphone, a nudge on an empty send;
- an animated step list and cards that rise in;
- all of it respecting reduced motion.

It speaks its own protocol, not AG-UI. Packaging that quality as an installable AG-UI chat lets any app add an excellent chat with one tag. It also gives formguide's interrupts a richer, configurable UI. The backend gains a few more interactive events for the chat to show.

## What Changes

**A new package `packages/agui-chat`**: `<agui-chat>`, a framework-free Web Component written in TypeScript, published as ESM for npm and as an IIFE bundle for a single `<script>` tag. A thin React wrapper, `@formguide/agui-chat/react`, comes with it. It works with any AG-UI agent:
- a built-in, dependency-free SSE transport to a run URL, or any `AbstractAgent` passed in;
- streaming text with the Cheese typewriter and word fade-in;
- tool calls shown as live steps;
- frontend tools registered from the page;
- an interrupt-renderer registry keyed by interrupt `type`;
- resume handling, thread restore, a microphone (Web Speech API), a growing composer and quick replies.

**Configurable from the UI.** Every feature can be switched on or off and tuned through attributes, a JS options object, CSS custom properties (theme tokens) and an i18n dictionary:
- mode: floating button plus side panel, inline, or full page;
- typing animation: words, plain or off;
- tool steps on or off, with labels;
- each card feature;
- the microphone;
- quick replies.

**A formguide plugin** (`@formguide/agui-chat/formguide`):
- sends `state` on each run;
- applies `ui_directive` through host callbacks;
- renders the field-change card with per-row checkboxes, old → new values, inline edit before accepting, a jump-to-field button and Undo after applying;
- renders the question card and the new interrupt kinds;
- provides tool-step labels for the built-in tools.

The host supplies `getState()`, `applyChanges(changes)` returning the new config, and optional `onDirective` and `revertChanges`.

**Backend additions:**
- Field changes carry `previous` and `previous_display` (the value before the change, in the form's format), so cards can show old → new and support Undo.
- A resume of a field-change card may carry `edited: {name: value}` when the user changed a value on the card. The model is told which values the user edited.
- `ask_user` gains `input`:
  - `{type: "date" | "time" | "datetime" | "number" | "text", min?, max?}` for a typed answer with a native picker;
  - with `field` set to a date field, the picker is chosen automatically.
- New tool `request_file` (interrupt `type: "upload"`). It asks the user to upload a document (`prompt`, `accept`, `multiple`, `field?`). It is answered with `{attachment_ids}` after `POST /attachments`, or skipped.
- New tool `confirm_action` (interrupt `type: "confirm"`). It is a yes/no confirmation (`title`, `message`, `confirm_label`, `danger`) for actions with side effects done by skill tools, answered `{accepted}`. `confirm_tools: [names]` in the config makes the named tools always ask first.
- Quick replies: after a turn, an optional `CUSTOM suggestions` event `{items: [string]}` comes before `RUN_FINISHED`. It is generated by a cheap model (the `memory` role chain) when `suggestions.enabled` is set in the config. Domain packs may also define static `starters` for an empty chat.
- Tool progress: the document researcher's sub-steps reach the client as `CUSTOM tool_progress {parent_id, name, input}`. Today they are emitted internally and dropped.

**The demo** uses the widget for its chat (the old React chat is removed). `examples/widget-html/` shows the one-script-tag setup.

**Not breaking:**
- The new interrupt types use the same `on_interrupt` channel.
- New fields on changes are additive.
- `suggestions` is off by default.

## Capabilities

### New Capabilities
- `chat-widget`: the installable AG-UI chat. Covers transport, streaming and animation behaviour, tool steps, the interrupt-renderer registry, frontend tools, thread restore, the composer, the microphone, configuration, theming, i18n and accessibility.
- `chat-widget-formguide`: the formguide plugin. Covers state, directives, field-change card features, question, upload and confirm cards, and tool labels.
- `quick-replies`: the suggestions event, its settings (`suggestions: {enabled, model, max, timeout}`) and static starters.
- `action-confirmations`: the `confirm_action` tool, its `confirm` interrupt, and tools that always need a confirmation (`confirm_tools`).

### Modified Capabilities
- `field-changes`: changes carry `previous` / `previous_display`; resumes may carry values edited on the card.
- `user-questions`: typed answers with an `input` type (date, time, number) and field-based pickers.
- `agui-protocol`: "Confirmation cards are interrupts" lists the `upload` and `confirm` kinds and their structured reasons; "Event order" covers `suggestions` and `tool_progress`.
- `attachment-extraction`: the `request_file` tool, its `upload` interrupt and how uploaded files reach the model.
- `domain-packs`: optional `starters`.

## Impact

- New code:
  - `packages/agui-chat/`: package.json, `src/` (element, transport, typewriter, renderers, i18n, theme, the formguide plugin, the React wrapper), tests (Vitest with happy-dom) and a Vite library build;
  - `examples/widget-html/`.
- Backend:
  - `agent/tools.py`: `previous`, `input` on `ask_user`, `request_file`, `confirm_action`;
  - `agent/graph.py`: the new pending kinds and the suggestions step;
  - `agent/interaction.py`: reading the new answers;
  - `guide.py`: transcript kinds `upload` and `confirm`, structured reasons, `suggestions` and `tool_progress` events;
  - `config.py`: the `suggestions` settings;
  - `domain/packs.py`: `starters`;
  - `prompts.py`.
- Frontend demo: `frontend/` switches its chat to the widget. `examples/copilotkit` is unchanged, apart from rendering the new types minimally.
- Docs:
  - a new `docs/chat-widget.md` covering install, every option, theming, plugins and writing a custom renderer;
  - updates to `ui-components.md`, `architecture.md`, `configuration.md`, the architecture pages (a new "Chat widget" page) and README.
- Dependencies: the widget has none at runtime. `@ag-ui/core` types are used only at build time. The React wrapper has a peer dependency on `react`.
- CI: the docs workflow is unchanged; a widget test job is optional (no CI exists for the backend today either).
