## Live turns

One user turn per scenario on a fresh conversation, against the public demo (Claude Haiku 5.5 for every role), 2 runs each, 14 November 2026. Cards are accepted and questions answered with their first option; the user's own time is not counted. The numbers are the server's own `run_stats`, so the network is not included.

| Scenario | First word | Whole turn | Tool calls | Tokens in / out | From cache |
| --- | --- | --- | --- | --- | --- |
| a question ("Where do I start?") | 3.5 s | 5.3 s | 1.5 | 16,000 / 490 | 72% |
| fill (name and birth date, card accepted) | **0.8 s** | 5.2 s | 2 | 24,431 / 318 | 92% |
| a choice (a question card, then a field card) | 2.4 s | 8.6 s | 4 | 41,079 / 774 | 92% |
| the business's documents (the car loan rate) | 4.7 s | 7.8 s | 3 | 24,410 / 672 | 93% |
| a booking (service, barber, day and slot: 10 tools in a row) | 1.1 s | 12.3 s | 10.5 | 86,540 / 1,223 | 80% |

<Compare title="The booking turn (10 tools in a row)" unit="seconds" better="lower" note="Same scenario, 11 Nov (Claude Opus 5.5 as the agent) and 14 Nov (Claude Haiku 5.5)."
  items={[{ label: '14 Nov, Haiku 5.5', value: 12.3, display: '12.3 s', highlight: true }, { label: '11 Nov, Opus 5.5', value: 22.9, display: '22.9 s' }]} />

Compared with the same scenarios on 11 November (Claude Opus 5.5 as the agent), the booking turn went from **22.9 s to 12.3 s** and the cache share from 65–75% to 80–93%. The model's time is almost the whole turn: Dushes adds about 10 ms.

```bash
cd backend && uv run python scripts/bench.py --base https://dushes-ai.fly.dev --repeat 3   # or your own server
```

## Dushes' own overhead

Measured offline on every `pytest` run, without a model, on the 221-field form. A change that makes any of these much slower fails the tests.

| Operation | Measured (laptop) | Budget |
| --- | --- | --- |
| build one turn's context (outline + focus) | 0.8 ms | 10 ms |
| diff two versions of the form | 0.9 ms | 10 ms |
| validate a 10-field card | < 1 ms | 10 ms |
| a whole turn through the graph with a 10-field card (scripted model) | 8 ms | 80 ms |

## Fewer taps

The cards are built to end a decision in one tap: a question about a field fills it when answered, a chip with values fills them at once with Undo, dependent dropdowns (make, then model) fill in one card instead of two. On the demo form, filling a car's make and model went from two cards and about 25 seconds to one card.

## Public agent benchmarks

<Compare title="Best reported success on public agent benchmarks" unit="%" better="higher" max={100} note="Autonomous agents, no user in the loop; numbers as reported on each benchmark's page. Not a Dushes score."
  items={[{ label: 'FormFactory: whole form filled', value: 2, display: '<2%' }, { label: 'Online-Mind2Web: tasks on live sites', value: 61, display: 'up to 61%' }, { label: 'τ²-bench: support tasks with tools', value: 88, display: 'about 88%' }]} />

There is no shared benchmark for an assistant that sits next to a form and fills it with the user's confirmation, so we do not claim scores on the public ones. They measure related but different things:

| Benchmark | Measures | Reported | How it relates |
| --- | --- | --- | --- |
| [FormFactory](https://arxiv.org/abs/2506.01520) (2025) | GUI agents filling 25 real-world web forms alone, from screenshots | end-to-end completion **under 2%** for the best zero-shot models; click accuracy under 10% | the hard part is finding fields on screen and matching values to them. Dushes reads the form's structure instead of pixels, and the user confirms every value |
| [τ-bench / τ²-bench](https://taubench.com) | tool-using agents talking to a simulated customer (retail, airline, telecom) | top pass^1 around 85–88% on τ²-bench, as the leaderboards report it; reliability drops over repeated trials (pass^k) | the closest in spirit: an agent, tools and a user in one conversation |
| [Online-Mind2Web](https://hal.cs.princeton.edu/online_mind2web) | web agents doing 300 tasks on live sites alone | about 42–61% success | autonomous browsing; Dushes keeps the user in charge of the page |

Why forms are hard for agents, and why the design matters: Baymard finds that about [17–18% of US shoppers abandoned an order because the checkout was too long or complicated](https://baymard.com/blog/cart-abandonment-rate), and that the average checkout still asks for 11.3 fields where 8 would do.

<Aside title="Numbers move">Model latency and leaderboards change week by week. The live table above is dated; run the benchmark on your own server and model for your numbers.</Aside>
