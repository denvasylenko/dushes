Every card of your own is made of these 19 blocks, stacked top to bottom. The label over each is its `type`:

<BlocksSheet />

A card of type `blocks` is a list of blocks, drawn in order. The server sends it from a [card spec](../../agents/ui-agent/cards-from-blocks/); you can also show one from your own code:

```js
const answer = await chat.showCard({ type: 'blocks', blocks: [
  { type: 'title', text: 'Is this your barber?' },
  { type: 'place', title: 'Maria Ivanova', subtitle: 'Barbershop on Arbat', rating: 4.9 },
  { type: 'row', label: 'Next free slot', value: 'Today, 16:30', icon: 'calendar' },
  { type: 'buttons', items: [{ id: 'yes', label: 'Yes, book her', style: 'primary' }, { id: 'no', label: 'Another barber' }] },
] })
// { action: 'yes', label: 'Yes, book her', values: {} }
```

Colours come only from the theme and a block's `tone` (`accent`, `ok`, `danger`, `muted`), so a card follows light and dark and every [theme](../themes/). Below, every block live; build cards from them in the [Playground](../playground/) (Your own cards).

## The blocks

| Block | Keys | Looks like |
| --- | --- | --- |
| `title` | `text`, `subtitle?` | the card's question and a grey line |
| `text` | `text` (inline markdown), `tone?` | a paragraph |
| `note` | `text` | a small grey line |
| `row` | `label`, `value`, `icon?`, `tone?` | a row of an iOS grouped list; rows next to each other form one list |
| `image` | `src` (https or data:image), `alt?`, `ratio?` (`16:9`, `4:3`, `1:1`) | a photo with rounded corners |
| `place` | `title`, `subtitle?`, `image?`, `rating?` | a person or a place: a photo or an initial, a name, a line, ★ 4.9 |
| `stat` | `value`, `label?`, `tone?`, `change?` ("+12%"; a leading minus turns it red), `spark?: [numbers]` | a big number or date, like a balance, with its change and a sparkline of how it got there |
| `chart` | `kind` (`bar`, `line`, `area`, `barList`, `stacked`, `meter`), `title?`, `subtitle?`, `unit?`, `data: [{label, value}]` or `labels` + `series: [{name, data}]`, `highlight?`; a meter takes `value`, `max?`, `limit?`, `label?` | a simple chart in the theme's colours, see Charts below |
| `diff` | `label?`, `from`, `to` | the old value struck through → the new one |
| `steps` | `title?` (`{left}` counts open steps), `items: [{label, done?}]` | a checklist with round ticks |
| `progress` | `value`, `max?` (100), `label?` | a thin bar |
| `swatches` | `name`, `items: [{id, label?, colors: [hex]}]`, `multiple?` | palettes to pick |
| `choice` | `name`, `options: [{id, label, off?}]` or `["a", "b"]`, `label?`, `multiple?`, `value?`, `required?`, `more?: {label, options}`, `depends?: {on, options: {<id>: [...]}}` | chips to pick, under a caption; `off` is shown but not choosable; `more` shows the rest in place; `depends` follows another choice (times of the chosen day) |
| `field` | `name`, `label?`, `input?` (`text`, `tel`, `email`, `number`, `date`, `url`), `placeholder?`, `value?`, `required?` | a field |
| `hours` | `name`, `label?`, `value?: [{days: [0..6], from, to}]` (0 = Monday), `presets?` | opening hours: presets in one tap, weekday chips, from–to, up to three pairs ; `AguiChat.hoursText(value, lang)` (or `hoursText` from `@formguide/agui-chat/formguide`) gives the line "Mon–Fri 09:00–18:00" |
| `preview` | `src` (https), `href?`, `title?`, `ratio?` (`16:10`, `9:16`) | a live, view-only thumbnail of a page; a tap opens `href` |
| `buttons` | `items: [{id, label, style?, fills?}]`, styles `primary`, `secondary`, `plain`, `danger`; `need?` | the card's actions; one primary. `fills: {field: value}` fills form fields on the tap, with Undo. While a `required` choice or field (or `hours`) is empty, the primary waits and the line under it says what is missing (`need`, `Choose: {x}` by default) |
| `links` | `items: [{kind, label, value}]` | actions that work at once, see below |
| `divider` | | a hairline |

An unknown block is skipped, so a newer server never breaks an older chat.

## Answers

A button with an `id` resolves the card with `{action, label, values}`: `values` has the choices, swatches and fields by `name`. The card folds into its result line ("✓ Yes, book her"), like the built-in cards.

## Charts

Six simple forms, each answering one question at a glance, all in the theme's colours (light and dark), with the numbers in a table under "Show data" and a text summary for screen readers:

| `kind` | For | Data |
| --- | --- | --- |
| `bar` | comparing a few amounts (up to a dozen): visits by day | `data: [{label, value}]`; `highlight: 'Sat'` keeps one bar in colour, the others grey |
| `line` | how something changed over time: a rate over six months | `labels` + `series: [{name, data}]` (two or more series get a legend) |
| `area` | one series over time, filled | like `line` |
| `barList` | a ranking with long names: top services | `data: [{label, value}]` |
| `stacked` | parts of a whole: a monthly payment | `data: [{label, value}]`; the legend shows each part's share |
| `meter` | a value against a limit: debt to income | `value`, `max?` (100), `limit?`, `label?`; over the limit it turns red |

```js
chat.showCard({ type: 'blocks', blocks: [
  { type: 'chart', kind: 'line', title: 'Rate, 6 months', unit: '%',
    labels: ['Jun', 'Jul', 'Aug', 'Sep', 'Oct', 'Nov'], series: [{ name: 'Rate', data: [17.2, 17.8, 17.5, 18.3, 18.6, 18.9] }] },
  { type: 'stat', value: '1 240 €', label: 'This month', change: '+12% vs October', spark: [700, 820, 780, 960, 1010, 1180, 1240] },
  { type: 'chart', kind: 'meter', title: 'Debt to income', value: 38, limit: 50, unit: '%' },
] })
```

Numbers follow the chat's language (`1,240 €` in English, `1.240 €` in German), the unit after them. At most 8 series and 60 points; no pies, no second axis. Columns, line and area are drawn by [Chart.js](https://www.chartjs.org) (MIT), loaded the first time such a chart shows (its own chunk with a bundler, `agui-chat.charts.js` next to the one-script build); the bar list, stacked bar and meter are plain HTML. More series take `--agui-series-2` … `--agui-series-8` (the first is the theme's accent).

## A picker

A booking (a day, a time, how many people, a name and a phone) is one card of type `picker`: one choice per group, times that follow the chosen day, unavailable options greyed out, "Other days" in place, and one button that waits until everything is chosen.

```js
const answer = await chat.showCard({
  type: 'picker', title: 'Book a table', submit: { label: 'Book' }, need: 'Choose: {x}',
  groups: [
    { name: 'day', label: 'Day', options: [{ id: 'fri', label: 'Fri 20' }, { id: 'sat', label: 'Sat 21', off: 'Closed' }],
      more: { label: 'Other days', options: [{ id: 'sun', label: 'Sun 22' }] } },
    { name: 'time', label: 'Time' },
    { name: 'people', label: 'People', options: ['1', '2', '3', '4'], value: '2' },
  ],
  depends: { time: { on: 'day', options: { fri: ['18:00', '20:00'], sun: ['12:00', '14:00'] } } },
  fields: [{ name: 'name', label: 'Name', required: true }, { name: 'phone', label: 'Phone', input: 'tel', required: true }],
})
// { action: 'submit', label: 'Book', values: { day: 'fri', time: '20:00', people: '2', name: '…', phone: '…' } }
```

It reaches `onAction` first (send the booking yourself, no model), or goes back to the model as the answer. The same card is blocks underneath: `choice` with `label`, `required`, `more`, `depends`, then `field` and `buttons`.

## Links

| `kind` | `value` | Does |
| --- | --- | --- |
| `call` | a phone number | `tel:` |
| `route` | an address | opens Maps |
| `web` | an https URL | opens it in a new tab |
| `calendar` | `{title, start (ISO, local time), minutes?, place?, details?}` | opens its choices in place: Apple Calendar (.ics), Google Calendar, Outlook |
| `share` | a text or URL | the share sheet (copies where there is none) |
| `copy` | a text | copies it, the link says "Copied" |
| `chat` | a text | sends it as the user's message |

A link without a value (no phone given) is left out. Images and links from data accept only https (and data: images): `javascript:` and the like are dropped.

## Handle a button yourself

For a button your code handles without the model (save a step, apply a style, send a booking to your server), give the plugin `onAction`; return true and the chat does nothing more. Redraw the card in place with `updateCard`:

```js
chat.use(AguiChat.formguide({ getState, applyChanges,
  onAction: async (card, action, chat) => {
    if (action.id !== 'save_hours') return false
    await fetch('/api/hours', { method: 'POST', body: JSON.stringify(action.values) })
    chat.updateCard(card.card_id, { blocks: [{ type: 'steps', title: 'All set', items: [{ label: 'Opening hours', done: true }] }] })
    return true
  },
}))
chat.addEventListener('agui:applied', (e) => scrollPreviewTo(e.detail.fields))   // what a card filled
```

A card of your own that blocks cannot express: `chat.renderers.set('booking', (card, ctx) => …)` draws it inside the chat, so the theme's tokens and classes apply; `AguiChat.blocksCard(payload, ctx, answer)` builds blocks inside it.

## What loads when

With a bundler the blocks are part of `@formguide/agui-chat/formguide`: every card is drawn at once. The one-script build leaves them out of `agui-chat.iife.js` and adds `agui-chat.blocks.js` (about 6 KB gzipped) from the same folder when the first run starts, or when the first card from blocks is shown, whichever comes first, so deploy the whole `dist` folder. A card shown before the file arrives keeps its room and fills in place; if the file cannot be loaded the card says so with Try again.

`AguiChat.blocksCard(payload, ctx, answer)` still returns its element at once: the blocks are drawn into that same element when they are here. To have them ready before your own renderer runs, wait for them once; `AguiChat.hoursText` is always there.

```js
await AguiChat.loadBlocks()   // agui-chat.blocks.js is here: blocksCard draws at once
chat.renderers.set('booking', (card, ctx) => AguiChat.blocksCard({ blocks: card.blocks }, ctx, (action, label, values) => ctx.resolve({ action, values })))
```

## Style them

Each block has a part, `block-<type>` (`agui-chat::part(block-place)`), and the card `blocks blocks-<name>`, so the page can restyle one kind of card. See [Themes and styling](../themes/).
