A form built with react-hook-form (or Formik, or `useState`) has no JSX skeleton or `{props, state}` config for Dushes to read. The schema bridge builds both from a short declarative schema, and `useFormguide` wires it to the chat. The form itself knows nothing about the chat.

```tsx
import { useForm } from 'react-hook-form'
import { AguiChat } from '@formguide/agui-chat/react'
import { useFormguide, type FormSchema } from '@formguide/agui-chat/react-hook-form'

const schema: FormSchema = {
  id: 'car_loan',
  title: 'Car loan',
  sections: [
    { name: 'applicant', label: 'Applicant', fields: [
      { name: 'full_name', label: 'Full name', required: true },
      { name: 'phone', label: 'Phone', help: '10 digits' },
    ] },
    { name: 'car', label: 'Car', fields: [
      { name: 'car_make', label: 'Make', type: 'select', options: ['Toyota', 'Honda'] },
      { name: 'car_model', label: 'Model', type: 'select',
        options: (v) => MODELS[v.car_make as string] ?? [], visible: (v) => !!v.car_make },
    ] },
  ],
}

export function Page() {
  const form = useForm()
  const [tab, setTab] = useState('applicant')
  const { plugins, ready } = useFormguide(form, schema, { onReveal: setTab })
  return (
    <>
      <MyForm form={form} tab={tab} />
      {ready && <AguiChat url="/agent/run" mode="inline" plugins={plugins} />}
    </>
  )
}
```

## The example, line by line

- **[`FormSchema`](../../reference/form-hooks/#formschema)**: Your form, described once: its `id`, sections and fields. Dushes has nothing else to read, because a react-hook-form form has no config of its own.
- **[`sections`](../../reference/form-hooks/#sectionschema)**: The tabs or steps of your form. Each has a `name`; that name is what `onReveal` gets.
- **[`fields`](../../reference/form-hooks/#fieldschema)**: One entry per input: its `name` (the same as in `register('full_name')`), a `label`, and a `type` when it is not text.
- **`options`, `visible` as functions**: Rules that depend on other values: the models depend on the make, and the model field is hidden until a make is chosen.
- **[`useFormguide(form, schema, options)`](../../reference/form-hooks/#useformguide)**: The hook: it tells the server about the form, sends the form with every message and puts accepted values into it with `setValue`.
- **[`onReveal: setTab`](../../reference/form-hooks/#useformguide-onreveal)**: "Open this tab." When the chat points at a field or fills one, it first calls `onReveal` with the field's section, here `'applicant'` or `'car'`, so the field is on screen. `setTab` is your own tab state's setter.
- **[`plugins`](../../reference/form-hooks/#useformguide-plugins)**: What the hook built for the chat. Pass it on as it is: `<AguiChat plugins={plugins} />`.
- **[`ready`](../../reference/form-hooks/#useformguide-ready)**: True once the server knows the form. The chat is rendered only then.
- **`<MyForm form={form} tab={tab} />`**: Your own form component, unchanged: it knows nothing about the chat.

## What you see

The chat appears next to the form. Ask "fill in my name, Sam Reed": a card proposes **Full name: Sam Reed**; accept it and the field fills, as if typed. Ask "where do I choose the model?": the **Car** tab opens, the field gets a ring and the cursor.

## Common mistakes

- **The chat never appears.** `ready` stays false when the layout could not be registered: the server is not running, or `url` points elsewhere. Read `error` from the hook: `const { plugins, ready, error } = useFormguide(...)`.
- **"Show me" does nothing for a field in another tab.** There is no `onReveal`, so the tab stays closed.
- **A card is accepted but the field stays empty.** The field's `name` in the schema is not the name your form registers (`register('full_name')`).
- **A field fills but is not shown or ringed.** The page finds a field by `data-name`, then by `name`: the input has neither.
- **A choice is saved in the wrong shape.** Your form stores the option's name or the whole option: set [`valueAs`](../../reference/form-hooks/#fieldschema-valueas).

## What the hook does

- Registers the layout once (`POST /agent/layouts`) and exposes `ready` and `error`.
- Builds the config for every run: labels, visibility, options and required flags from the schema (rules may be functions of the current values), errors from `formState.errors`.
- Applies accepted cards with `setValue`, converting choice values to the form's own format: `valueAs` is `id` (default), `option` or `name`.
- Handles "show me": calls `onReveal(section)` so your page can open the tab, then scrolls to and focuses the field found by `data-name` or `name`, rings it, and shows the agent's hint ("Enter 10 digits here") in a small bubble under it. It also does this after every card, tap answer or action chip that fills a field, so the user sees what changed.

The framework-free bridge underneath is `schemaForm(schema, access)` from `@formguide/agui-chat/formguide`; the [live demo](../../) on the home page uses it with a plain DOM form. Every option: [React and schema API](../../reference/form-hooks/). Behaviour contract: [form-adapters](../../reference/specifications/form-adapters/).

## Run the example

Start the demo server (port 8000), then in [`examples/react-hook-form/`](https://github.com/denvasylenko/dushes/tree/main/examples/react-hook-form):

```bash
npm install && npm run dev      # http://localhost:5175, proxies /agent to :8000
npm install && npm run build    # or open it from the demo server: http://localhost:8000/examples/react-hook-form/
```

The demo server mounts the build only if it existed at start-up: restart it after the first build.
