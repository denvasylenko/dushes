## Before it faces the internet

<Steps>

1. **Auth in front.** Mount the router behind your own dependency, or a gateway. A thread id is the only key to a conversation.

   ```python
   from fastapi import Depends, FastAPI
   from formguide.server import create_router

   app = FastAPI()
   app.include_router(create_router(guide), prefix="/agent", dependencies=[Depends(require_user)])   # require_user: your auth
   ```

2. **Protect the manager endpoints** harder than the chat: `/kb/*` changes what the agent tells every user.

3. **CORS** to your origins only: `create_app(..., cors=["https://my.app"])` or `formguide serve --cors https://my.app`.

4. **Rate limiting** per user at the gateway: every message is a model call.

5. **Never `debug=True` in production**: `GET /debug/{thread_id}` shows the model's history to anyone with the id.

</Steps>

## Known limits

- The document endpoints (`/kb/*`) have no auth of their own: anyone who reaches them can upload or delete documents. Put them behind your auth, as above.
- Chat text and attachments are not tokenized: personal data reaches the model as the user wrote it. Strict regimes need their own redaction in front of the server.
- Field search matches words, not meaning; the document index already takes embeddings.
- Live conversation tests run on Anthropic models; OpenAI and Azure are covered by offline payload checks only.

## A public demo host

This project's own host (`docs_ai.host`, deployed from `deploy/docs-ai/` as https://dushes-ai.fly.dev) serves the docs, Ask AI and a live demo anyone can use, so it limits the demo. Copy the pattern if you put an agent in front of the public.

| Variable | Default | Limit |
| --- | --- | --- |
| `DEMO_PER_VISITOR_DAY` | `10` | messages per visitor a day, by the `X-Demo-Visitor` header the landing sends |
| `DEMO_PER_IP_DAY` | `60` | messages per address a day |
| `DEMO_PER_THREAD` | `15` | messages per conversation |
| `DEMO_PER_DAY` | `500` | messages for the whole site a day |
| `DEMO_RUNS_DAY` | `300` | runs a day, card answers and hand-offs included |
| `DEMO_COST_DAY` | `5` | US dollars a day, from each run's real tokens |
| `DEMO_PRICES` | unset | `"input,output,cache_read,cache_write"` dollars per million tokens of the hosted model; unset turns the cost cap off |
| `DEMO_KEEP_HOURS` | `24` | the demo's transcripts and checkpoints are deleted after this many hours (the hourly clean-up runs on Fly or when this is set) |
| `DEMO_LINK` | the quickstart | where a refused visitor is sent |

Card answers and hand-offs don't count as messages, but they do count as runs and toward the cost. A refused run gets HTTP 429 before any stream starts:

```json
{"detail": "...", "code": "demo_limit", "reason": "visitor", "link": "/get-started/quickstart/"}
```

`reason` is one of `visitor`, `ip`, `thread`, `site`, `runs`, `cost`. Uploading business documents is off on this host. The landing's form is registered at start-up from `backend/demo/landing/`, and `GET /agent/layouts/<form_id>` returns its `{jsx_hash, form_id}`, so the public page calls no write endpoint.

## What to keep on disk

`data_dir` holds learned field dependencies, registered layouts, documents, attachments and transcripts. Mount it as a volume, or point each store elsewhere (a SQL checkpointer, your own transcript store, a vector store).

## Container

```dockerfile title="Dockerfile"
FROM python:3.12-slim
WORKDIR /app
RUN pip install "formguide[all] @ git+https://github.com/denvasylenko/dushes.git#subdirectory=backend"
COPY formguide.yaml ./
COPY domain_packs/ ./domain_packs/
COPY skills/ ./skills/
ENV FORMGUIDE_CONFIG=/app/formguide.yaml
VOLUME /app/data
CMD ["formguide", "serve", "--host", "0.0.0.0", "--port", "8000", "--cors", "https://my.app"]
```

```bash
docker run -p 8000:8000 -e ANTHROPIC_API_KEY=... -v formguide-data:/app/data my/formguide
```

<Aside>Behind a proxy, turn off response buffering for `/agent/run` (it streams server-sent events). The server already sends `X-Accel-Buffering: no` for nginx.</Aside>
