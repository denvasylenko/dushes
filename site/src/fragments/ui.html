1. What you send: the skeleton once, the form with every message

On page load, POST /agent/layouts {jsx, form_id} returns a jsx_hash and a list of warnings (read it). Then every run carries state = {config: {props, state}, jsx_hash, form_id, ui} with the latest config.

JSX rules

  • every element has a name, unique in the form
  • only the tag and name are read; labels and flags go in props
  • text between tags is static text the agent can quote
  • no {…} expressions: conditions are visible: false
  • tags are mapped to roles; your own library, and how its components store values, goes in components:

Default tags

  • containers: Form, Tabs, Tab, Accordion, Section
  • fields: Input, TextArea (text), NumberInput, DatePicker, Dropdown (select), RadioGroup (radio), MultiSelect (multiselect), Checkbox (bool), FileUpload
  • a React form without its own config: useFormguide builds the skeleton and the config from a schema

A field that is in the JSX but has no props entry counts as hidden. ui is {activeTabs: {tabsName: tabName}, openAccordions: [...], focused, now}: what the user sees right now.

2. Value formats: the agent writes what your component stores

Every library stores values its own way: a dropdown may keep the whole option, just "auto", or a label; choices may be options: [{id, name}] or items: [{value, label}]; a toggle may hold "Y"/"N". Describe each component tag once, and the agent reads your form correctly and writes card and prefill values in exactly your format.

components:
  fields:
    Select:      {role: select, value: id, options_prop: items}   # stores "auto"
    RadioGroup:  {role: radio, value: id}
    MultiSelect: {role: multiselect, value: ids}                 # ["sms", "email"]
    Toggle:      {role: bool, true: "Y", false: "N"}
    Calendar:    {role: date, format: "%d.%m.%Y"}
    Amount:      {role: number, value: string}                   # "250000" instead of 250000
    Phone:       {role: text, codec: "my_app.codecs:PhoneCodec"}  # anything else

To check the setup, register the form with its initial config, POST /agent/layouts {jsx, form_id, config}, or run formguide check --jsx form.jsx --form-config config.json. The warnings name each field the agent cannot read and the key to set.

3. What comes back

The card, CUSTOM on_interrupt, a JSON string. The run stops until the user answers. Every value is in your component's format and already checked: the field is visible and editable, the option exists, the date is real.

{ "type": "set_fields", "card_id": "cc9fefa2fb8e",
  "changes": [{ "name": "loan_type", "label": "Loan type",
                "value": { "id": "auto", "name": "Car loan" },   // goes to your backend
                "display": "Car loan",                            // shown on the card
                "reason": "You said car loan",
                "reveal": [{ "type": "tab", "tabs": "main", "tab": "tab_loan" },
                           { "type": "accordion", "name": "acc_loan_params" }] }] }

Keep some rows: a checkbox per row; send only the ticked changes to your backend and resume {accepted: true, config, names: ["first_name", "last_name"]}. The agent is told which were declined. Each change also has previous / previous_display (old → new, Undo), and a value the user corrected on the card goes back as edited: {name: value}.

The question card, the same on_interrupt with type: "ask": the agent asks when the user must choose between known options or the request is ambiguous. Buttons for a single choice, checkboxes for multiple, a text box when allow_text. When it is about an editable choice field, the options carry the form-format value and the card has applies: true: one tap fills the field (with Undo) and the resume carries the new config, so no field-change card follows. Typed text only answers.

{ "type": "ask", "card_id": "a41c09e2d7f3", "question": "What kind of loan do you need?",
  "options": [{ "id": "auto", "label": "Car loan" }, { "id": "mortgage", "label": "Mortgage" }],
  "multiple": false, "allow_text": true, "field": "loan_type" }

resume: { answer: { ids: ["auto"] } }   // or { answer: { text: "..." } }, or { accepted: false } to skip

4. Components: the checklist

Every element

  • data-name="<name>" on its outer DOM node
  • reads its props by name; applies the parent's hidden and locked state
  • can pulse briefly and show a hint

Fields

  • store values in the default formats, or describe the tag in components.fields
  • choices come from props, never a hard-coded list
  • show error under the field

Tabs and accordions

  • controlled: the open tab and open accordions live in page state
  • so a directive can open them, and you can send them as ui

The page

  • register the JSX once, keep jsx_hash
  • send the latest config with every run
  • draw on_interrupt by type: set_fields or ask
  • after a reload, GET /agent/threads/{id} returns pending_card (a card or a question): show it again
